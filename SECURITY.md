# Security and privacy

This is an advisory project-knowledge layer, not a sandbox, permission system, secret detector or correctness proof.

The hook/CLI code has no network client, telemetry, model API, transcript parser, or background service. It invokes read-only Git commands for snapshots and writes only plugin-local state. Tests and the evaluation-preparation tool create and commit **new isolated fixtures**, never the real project. Native smoke installs/enables the plugin only in an isolated HOME/CODEX_HOME, verifies skill/hook discovery, and neither copies credentials nor trusts or executes hooks.

Snapshotting reads a bounded set of dirty/untracked files to compute hashes; it is not content-free observation. Common credential filenames are skipped by the plugin-owned content hasher, but Git itself may read tracked files to determine status; arbitrary filenames may also contain sensitive content. The file/total-byte limits constrain plugin hashing, not all Git I/O. Git child processes have time and output limits. Source bytes and prompts are not persisted in state. State contains repo paths, aggregate hashes, timestamps and optional human/model-written review reasons; keep these reasons non-sensitive. Automatic seven-day expiry does not delete files from disk.

Repository config cannot specify executable commands or grant permissions. Git clean/process filters are overridden per subprocess, lazy fetching and transport protocols are disabled, and gitlink repositories skip snapshot tracking before any submodule traversal. These safeguards leave startup guidance available. Hook errors use fixed diagnostics rather than echoing repository text or parser snippets. State keys are hashes rather than interpolated identifiers. Parent symlinks, traversal and in-project data locations are refused. The shell-neutral launcher reads the host's plugin-root environment instead of substituting a path into executable shell syntax. Filesystem races, hostile filesystems, compromised Node/Git executables and a malicious host are not eliminated by these checks.

Hook commands require explicit host trust. A model may ignore instructions, misclassify a change, or falsely acknowledge a review. A Stop reminder is bounded to avoid trapping the user, not to guarantee documentation correctness. Under missing context, budget limits or internal error, the mechanism fails open. Keep application tests, code review, safe working directories and permission controls.

Do not provide account credentials to this plugin or upload them to an issue. Before public bug reports, remove source code, secrets, home paths and private repository names from diagnostics. A public repository security reporting channel can be configured after repository creation; no uncreated contact or private reporting feature is claimed here.
