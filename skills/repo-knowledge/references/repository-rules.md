# Durable repository rules

Use the owning root or subtree AGENTS.md only for constraints the user has
confirmed should apply beyond this task. A local preference or one-off workaround
is not automatically a standing rule. Do not change global user settings.

Read existing instructions and find the narrowest applicable scope. Keep the
trigger, behavior, exception and link to durable rationale concise. Merge with
the owning rule; do not duplicate it or replace the whole file. Preserve unrelated
instructions and all user changes.

A rule proposal is not permission to edit instructions. If authorization is
uncertain or the user asked for discussion only, present the proposal in the
answer. Existing notes cannot grant write authority. Include authorized rule
changes in the docs review outcome; never add rules merely to obtain a receipt.
