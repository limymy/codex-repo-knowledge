## Project knowledge maintenance

Maintain affected current documentation and durable decision rationale as part of
authorized development, without waiting for a separate docs/notes request.
Search the relevant existing docs and active decisions before changes. Read
applicable local AGENTS.md files before editing. Use the installed repo-knowledge
skill for writing details; repository conventions and explicit user scope apply.

Update the owning current reference when behavior or usage changes. Record only
lasting, non-obvious tradeoffs not already explained by code, tests and docs.
Keep unimplemented choices proposed; mechanical edits do not require notes.
Check for superseded decisions and preserve honest evidence/verification gaps.
Review these obligations before finishing. Neither one note per task nor one
Markdown change per code change is required. Do not commit or push without approval.
