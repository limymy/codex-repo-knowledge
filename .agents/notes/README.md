# 开发决定

这里记录插件自身值得长期保留的设计理由，不是使用者的聊天记录。创建前搜索已有维护位置；只有丢失后可能导致重复调查、撤销有意取舍或重犯重要错误的理由才值得记录。机械修改与文件整理不强制写新决定。通用资格和写作要求见[决定规范](../../skills/repo-knowledge/references/decisions.md)。

## 目录与命名

本仓库采用 `.agents/notes/{lifecycle}/{class}/YYYY-MM-DD-topic-title.md`。文件名使用英文 kebab-case；新记录日期代表首次提出日期，已有记录沿用原始日期，不猜补未知的更早日期。后续实施、澄清或替代的实际日期在正文中说明，不能用移动文件的日期冒充决定或实现日期。

- `lifecycle`：活动记录按 `proposed`、`implemented`、`rejected` 分置；冻结的历史记录进入 `archived`
- `class`：按所解释的主要问题选择 `feature`、`bug-fix`、`simplification`、`architecture`、`process` 或 `testing`
- 只有存在实际记录时才创建对应目录；不预建空树，也不为同一决定复制多个分类版本

当前只有三篇已实施的架构决定，因此实际目录只有 `implemented/architecture/`。原生打包记录决定的是交付清单与宿主发现机制，故归 `architecture`；若以后记录压缩、发布工具或团队操作流程，则按其实际主题归 `process`，不为目录整齐强行沿用分类。此组织方式参考 DSH 的生命周期与分类，固定来源见[参考来源](../../docs/sources.md)；它不要求引入 DSH 的双语配对、篇幅预算或其他发布流程。本仓库正文以中文维护。

## 状态与维护

现有记录继续保留用于选择性校验的决定 HTML 标记、`# Decision:`、单独的 `Status:` 行及校验器要求的英文节标题，不翻译这些机器接口。正文负责说明真实问题、选择、替代方案、后果和证据缺口；格式通过不代表理由真实或设计正确。

活动目录与状态相符：`proposed` 记录尚未实施的方案；`implemented` 说明已实现的选择；`rejected` 保留被否决的方案及真实拒绝理由。实施或否决已有方案时维护同一条记录，按状态移动，保留原始日期及实际变化日期，修复所有入链，并同步所属的当前文档。部分实施不能把未完成部分写成已完成。

本地可选校验器还接受 `Status: superseded`，用于表示一条已被取代的决定；这不是 DSH 的活动生命周期目录，不能据此创建 `superseded/` 树。完整替代时新增或复用真正的替代决定，旧记录保留原结论和唯一理由，以 `Status: superseded` 及 `## Superseded by` 链接替代者，替代者也链接历史，然后将旧记录移入 `archived/{class}/` 并修复入链。仅部分替代时明确范围，双向链接，仍有效的保证继续留在活动记录中。

`archived` 表示冻结历史，不是校验器的 `Status:` 值；归档不应编造新状态或改写旧理由，也不能只因年代或长度归档。未被其他决定替代的历史保留其最后有效状态和归档原因；旧记录不再作为当前行为或权限的依据。校验器会跳过所有名为 `archived` 的子树，因此归档内容与入链仍需人工检查。

当前路径、符号和默认值随所属实现维护。决定反转时保留原有因果理由及真实备选，不把旧决定悄悄改成相反结论。移动、拆分或合并记录时保留独有证据、限制与日期归属，并修复入链；仅拆开原本捆绑的独立决定不等于推翻选择，也不需要为整理动作再写一篇决定。

## 当前决定入口

- [有界提醒与宿主回执](implemented/architecture/2026-09-28-bounded-advisory-review.md)：为什么维护判断仍由 Agent 作出、状态由宿主保存，以及单次提醒、重放保护和降级放行的取舍
- [原生打包](implemented/architecture/2026-09-30-native-packaging.md)：为什么采用受测宿主实际能够发现的 manifest 布局，以及安装、发现与受信执行之间的证据边界
- [Git 隔离](implemented/architecture/2026-09-30-git-isolation.md)：为什么禁用过滤器与传输、对子模块项目放弃自动快照跟踪，以及最终状态目录不能落入项目的约束

三条决定仍有效，各自负责不同边界。[架构](../../docs/architecture.md)提供组件与知识归属地图，[Hook 协议](../../docs/subsystems/hook-protocol.md)维护精确机制，[测试说明](../../docs/testing.md)维护验证方法，带日期的运行结果和未验证分支归[验证记录](../../VERIFICATION.md)。
