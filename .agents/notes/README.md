# 开发决定

这里记录插件自身值得长期保留的设计理由，不是使用者的聊天记录。

创建前搜索已有维护位置。机械修改不强制写笔记；规则、当前事实和取舍分别维护。参考 [决定规范](../../skills/repo-knowledge/references/decisions.md)，记录真实替代方案与验证限制。

路径等事实随代码维护；决定改变时新增替代记录，保留仍有价值的理由并相互链接，不把旧决定悄悄改成相反结论。

- [原生打包与 Git 隔离](2026-09-30-native-packaging-and-git-isolation.md)：为什么采用已观察可发现的 manifest 布局，以及为何子模块项目保留职责但放弃自动快照跟踪

两条决定仍有效，各自负责不同边界。当前字段、执行顺序和限制在 [架构](../../docs/architecture.md) 完整维护；运行结果和未验证分支在 [验证记录](../../VERIFICATION.md) 维护。
