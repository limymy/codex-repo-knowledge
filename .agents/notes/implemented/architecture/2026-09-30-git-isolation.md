# Decision: 以防御性 Git 观察维持本地隔离边界

<!-- repo-knowledge:decision -->
Status: implemented

## Problem
看似只读的 Git 状态命令，还可能执行 clean/process 过滤器、子模块本地过滤器，或触发延迟获取传输。知识维护 Hook 应当只提供本地、有界的观察与提醒，不能因为读取状态就运行仓库配置中的程序或访问网络。宿主给出的数据根目录位于项目外，也不必然意味着最终推导出的状态目录仍在项目外。

## Decision
在每个 Git 子进程中，禁用已配置的过滤器可执行程序和延迟获取传输。在运行状态检查之前检测 gitlink；对于包含子模块的仓库，降级放行，不再自动跟踪快照。这样避免在读取状态时深入具有独立可执行 Git 配置的子模块，同时保留长期有效的维护指导。

根据项目根目录校验最终推导出的状态目录，而不只校验宿主给出的数据根目录。校验对象必须涵盖推导后的落点，才能维持运行状态不写入项目的边界。当前执行机制由 [Hook 协议](../../../../docs/subsystems/hook-protocol.md)维护，文件与进程访问边界见[安全说明](../../../../SECURITY.md)。

## Alternatives considered
递归清理所有子模块配置，会引入规模更大且易受竞态影响的配置遍历器；对含 gitlink 的仓库跳过提醒，则可以维持仅提供提醒的职责边界。所选方案接受少覆盖一类仓库的代价，不用复杂的递归清理换取自动提醒。

原记录保留了 Git 过滤器与传输标记复现，以及状态目录包含关系的回归证据，但没有记录其他 Git 隔离或状态目录方案的系统比较；这里不补造未进行过的备选实验。

## Consequences
包含子模块的项目仍保留长期有效的维护指导，但失去自动改动提醒。Git 在评估状态时仍可能读取受跟踪的内容；插件的哈希计算限制并不是 Git 的总 I/O 预算。该选择缩小了已知可执行配置与传输风险，不把 Git 观察变成沙箱或工作树隔离机制，也不证明变化属于某个 Agent。

最终状态目录校验保护“不向项目写入运行状态”的边界；它不消除并发文件系统变化或其他环境风险。受保护的本地状态与项目文档仍有不同的写入主体，知识判断和自报回执的限制见[有界提醒决定](2026-09-28-bounded-advisory-review.md)。

## Evidence
本记录保留原合并记录 `2026-09-30-native-packaging-and-git-isolation.md` 中属于 Git 观察及状态目录隔离的 2026-09-30 决定、取舍与证据。2026-10-05 将两项独立决定拆开并回溯性澄清其边界；这不是新的隔离实现，也不声称本次重新运行了原生或模型验收。

- 已观察历史：Git 过滤器及传输标记复现、状态目录包含关系的回归测试，以及相应历史故障注入，见[验证记录](../../../../VERIFICATION.md)。原检查未更改 Hook 信任设置或使用者配置。
- 当前实现：[git.mjs](../../../../scripts/lib/git.mjs)在子进程内覆盖过滤器与传输配置，并在状态检查前检测 gitlink；[store.mjs](../../../../scripts/lib/store.mjs)检查推导后状态路径与项目根的包含关系。
- 确定性证据：[安全测试](../../../../tests/safety.test.mjs)覆盖 clean/process 过滤器标记不执行且仓库配置不变、gitlink 返回不完整快照、缺失 promisor 对象不触发传输，以及推导出的状态目录与仓库重合时，无论只打开还是创建都拒绝，且不写入项目。
- 限制：这些是具体保护分支的确定性回归，不证明任意 Git 配置、平台或并发文件系统下都安全；该测试文件中的延迟获取传输用例跳过 Windows。运行日期、环境和未验证范围以验证记录为准，不能从用例存在推断本次运行通过。
